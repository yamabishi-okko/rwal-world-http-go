## 852 WebSocket — サーバとブラウザでリアルタイム通信
このフォルダは、WebSocket を使ったブラウザとサーバの双方向通信の最小サンプルです。
8.5.3（WebSocket）の内容に沿って、入力したメッセージがリアルタイムでサーバに送られ、サーバから即時に返されます。
サーバとブラウザが 常時接続 を維持
入力したメッセージが即座にサーバへ
サーバの返答がすぐに画面に反映される
HTTP/1.1 ではリクエストごとに接続が切れるが、WebSocket では一度「握手」すればそのまま繋ぎっぱなしで通信できる。

### 前提
Go 1.20+（1.22 推奨）
モダンブラウザ（Chrome / Firefox など）
このフォルダにあるファイル：
server.go     # Go製のWebSocketサーバ
public/
  index.html  # 入力フォーム付きUI
  main.js     # WebSocketクライアント処理


### 起動
サーバの起動
cd ch08/85_js_comms/852_websocket
go run .


### 遊び方（UI で試す）
ブラウザで http://localhost:18888 を開く
テキストボックスに好きな言葉を入力して送信
サーバからの返答がすぐに下に表示される
(秘密の言葉を入力すると・・・)


### 内部のつながり
server.go
WebSocket サーバを起動
/ws への接続を待ち受ける
受け取ったメッセージをそのまま返す（エコー）
特定のワードなら特別な返答を返す

public/index.html
入力欄
ログを表示する <div id="log"> を用意

public/main.js
new WebSocket("ws://localhost:18888/ws") で接続
入力内容を送信 (ws.send(...))
サーバからのメッセージを受け取ってログ表示


### 処理の流れ（図解）
💻 ブラウザ (index.html + main.js)
「➡️ 入力したよ！サーバに送るね」
│
▼
🖥 サーバ (server.go)
「📩 メッセージ届いた！そのまま返すよ」
│
▼
💻 ブラウザ
「📩 サーバから返す: 入力内容」


### 学べること
WebSocket の基本構造
HTTP Upgrade により常時接続を確立する
クライアントとサーバが対等に「イベント駆動」で通信できる
HTTP/1.1 の限界（リクエスト・レスポンス型）を超えた仕組み
リアルタイム性が必要なアプリ（チャット・ゲーム・株価更新など）の基礎

### まとめ
このフォルダのサンプルを動かすことで、
「WebSocket とはなにか」「どうやってサーバとブラウザが繋がるのか」を手を動かしながら体験できます。

# 854 WebTransport — HTTP/3 上の次世代通信API
このフォルダは、WebTransport を使ったサンプルのためのものです。
WebTransport は HTTP/3 (QUIC/UDP) を基盤にした新しい通信プロトコルで、
「WebSocket や SSE では足りない部分」を補うために設計されています。

## なぜ WebTransport なのか？
🌐 これまでの選択肢との違いを整理すると：
Fetch API / XHR
単発リクエスト（リクエスト → レスポンス）には便利。
でも「継続的な通信」や「低遅延なやりとり」には向かない。

## SSE (Server-Sent Events)
サーバ → クライアントへの一方向のイベント通知に特化。
ただし「クライアント → サーバへの即時送信」は別手段が必要。

## WebSocket
双方向の小さなメッセージをやりとり可能。
でも TCPベースのため「順序」「再送制御」で遅延が発生する。
動画やゲームなど「多少のパケット欠落はOK、でも速さが大事」な用途には不向き。

## WebTransport
QUIC (UDPベース) の HTTP/3 上で動作。
ストリームとデータグラムを両方サポート。
🎬 ストリーム → 信頼性重視（動画配信、ファイル転送など）
🎮 データグラム → 非信頼・低遅延（ゲーム、センサー情報など）

つまり「必要に応じて信頼性と低遅延を使い分けられる」のが最大の特徴。

## このフォルダで試せること（予定）
### 双方向ストリームのエコー
クライアントから送信した文字列を、サーバがそのまま返す。

### データグラムの往復
「順序や再送保証のない」メッセージ送信を実際に体験。
（ゲームや音声チャットの雰囲気が掴める）


## 学べること
HTTP/3 + QUIC 上で動く最新のブラウザ通信の雰囲気
WebSocket と比べたときのメリット（低遅延・選べる信頼性）
ストリーム通信とデータグラム通信の違い

## 注意点
現在（2025年）、ブラウザ対応は Chrome 系が中心。Safari/Firefox はまだ限定的。
TLS 証明書が必須で、http:// では動作しません。
ネットワーク環境（ファイアウォール・プロキシ）によっては UDP がブロックされる場合があります。

## まとめ
WebTransport は 「WebSocket の次の選択肢」 として登場した仕組みです。
双方向通信・低遅延・複数ストリームを同時に扱えるので、
将来的には リアルタイムゲーム・映像配信・IoT通信 で広く使われると期待されています。
